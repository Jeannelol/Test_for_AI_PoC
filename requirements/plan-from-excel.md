# 需求拆分 v1.0 对照与计划（原型 / UX / UI / 前端）

基于 `requirements/需求拆分v1.0.xlsx`（工作项列表）与现有前端（HKMarketChat.tsx + 拆分组件）对比整理。

## 已覆盖/部分覆盖
- 首页场景卡片（Epic 2.1/2.2）：已有 6 个卡片展示；未实现点击填充示例问题或触发不同参数。
- 聊天输入输出（Story 3.1.1/3.1.2）：输入框、消息气泡、Enter 发送、助手回复占位已具备。
- 侧边栏展开收起、历史列表展示（Story 3.3.1/3.3.2）：UI 有折叠按钮和列表；无持久化。
- 新建对话（Story 3.4.2）：按钮返回欢迎页并重置消息。

## 缺口与待办（按需求分组）
### 1) 用户访客模式与会话管理（Epic 1）
- 临时 ID / 昵称创建（Stories 1.1.1, 1.1.2）：缺 UI 与逻辑。  
  - 原型/UX：首屏弹窗或顶部条提示生成昵称/ID。  
  - 前端：表单/弹窗组件 + 本地存储/后端接口占位。
- 会话持久化（Stories 1.2.1, 1.2.2）：缺本地/后端存储与加载。  
  - 前端：接入 API（React Query）或 localStorage 持久化；会话/消息拉取、排序。

### 2) 首页场景入口（Epic 2）
- 场景触发填充示例问题（Story 2.2.1）：卡片点击后填充输入框并聚焦。  
- 场景参数/工作流分支（Story 2.2.2）：为卡片配置 `scenarioKey`，发送时携带参数；预留调用后端工作流。

### 3) 对话体验与管理（Epic 3）
- 多轮上下文（Story 3.2.1）：需会话上下文保持与发送时携带 conversationId；后端接口需要支持。  
- 历史搜索（Story 3.4.1）：搜索框当前无逻辑；需过滤/搜索会话。  
- 对话重命名（Story 3.4.3）：无 UI/逻辑；需 inline rename 输入与提交。  
- 状态提示：发送 pending/failed，加载态、错误提示（未在需求表中但实践必需）。  
- 输入多样：文件/图片占位尚未实现（非表格明确，但可能扩展）。

### 4) 合规与安全（Epic 4.x）
- 输入合规检查（Story 4.1.1）：需前端拦截/后端校验返回。  
- 不合规话术（Story 4.1.2）：需统一提示组件/气泡样式。  
- 意图分支（Story 4.2.x）：需增加前端工作流参数/提示，后端识别。  
- HKEX 知识库映射（Story 4.3.x）、真实数据调用（Story 4.4.x）：前端需支持展示结构化数据/卡片，后端提供接口。  
- 结构化回答模板（Story 4.5.x）：前端需渲染多段落/分区（市场全景、行情、财务、资金、行业、风险提示）并支持摘要/列表/标签。

## 前端计划（迭代建议）
### 短期（迭代 1）
- 卡片点击填充示例问题 + 聚焦输入（2.2.1）。  
- 搜索框支持会话过滤（3.4.1）。  
- 对话重命名 UI + 本地更新（3.4.3）。  
- 发送 pending/failed 状态 + 错误提示；React Query loading/error 显示。  
- `USE_API` 开关接入真实接口（会话列表/消息发送），至少打通基础对话链路。

### 中期（迭代 2）
- 临时 ID/昵称弹窗（1.1.x），与会话持久化（1.2.x）联动（localStorage + API）。  
- 卡片场景参数透传（2.2.2），发送时附带 `scenarioKey`。  
- 上下文保持：conversationId 贯穿消息列表与发送（3.2.1）。  
- 合规提示：统一错误/合规气泡；输入拦截与后端返回话术（4.1.x）。

### 结构化回答与数据展示（迭代 3）
- 为结构化输出准备组件：分区卡片（市场全景、行情、财务、资金、行业、风险提示），支持列表/标签/表格。  
- 数据卡片：指数/个股行情卡、新闻摘要卡；支持表格/标签。  
- 意图分支反馈：在 UI 上标记当前工作流/场景。

## 原型/UX 提示
- 入口体验：首访弹窗或顶部条收集昵称/同意临时 ID。  
- 状态可视化：发送中骨架、失败提示、重试按钮；加载时禁用发送。  
- 搜索/重命名：侧栏内联输入 + 保存/取消；搜索过滤列表。  
- 场景卡片：点击后在输入框显示模板，并在聊天区提示“已选择场景：xxx”。  
- 合规提示：使用显著的提示气泡/卡片，提供“修改问题”引导。

## 实现提示（代码）
- `Sidebar`：增加搜索逻辑、重命名交互、会话持久化（React Query + mutation）。  
- `ChatInputBar`：支持外部填充示例问题；禁用态/加载态。  
- `HKMarketChat.tsx`：管理 `scenarioKey`、`conversationId`、用户标识；将发送参数透传到 API。  
- 新增组件：结构化回答卡片（行情/财务/风险）、合规提示卡、错误/加载 Skeleton。  
- 存储：localStorage 保存 guestId/nickname、最近会话；API 接口对接后替换。
