# 交互说明（初版） — 访客身份 / 昵称流程

> 用途：沉淀关键交互流程与数据约定，便于后续设计迭代与落地。可直接在本文件上修改/补充。

## 1) 访客身份弹窗（首次/清除后）
- 触发：首次访问或清除本地访客数据后自动弹出，不因头像点击出现。
- 显示：访客 ID（格式 `GUEST-` + 5 位随机串）、加入时间、对话数量占位、隐私说明；可输入昵称（可选）。
- 操作：
  - “确认并继续”：保存昵称（如为空则用 `访客<后三位>`）、保留 ID 与加入时间到 localStorage，关闭弹窗。
  - “稍后设置”：跳过昵称，保存 ID/加入时间，关闭弹窗。
- 数据存储：`guestId`，`guestNickname`，`joinDate`，`hasVisited` 存于 localStorage。

## 2) 头像点击 → 个人资料弹窗
- 触发：页面右上头像点击。
- 显示：访客 ID、加入时间、对话数量、隐私说明；支持编辑昵称。
- 操作：
  - “保存”：更新昵称写回 state + localStorage，关闭弹窗。
  - “清除所有数据”：清空访客相关 localStorage，关闭弹窗，并重新生成访客 ID/加入时间；下次将看到访客身份弹窗。
  - “关闭”：不改数据，仅关闭。

## 3) 数据约定
- 访客 ID：格式 `GUEST-` + 5 位数字/字母，生成后存储于 localStorage 用于后续访客数据关联。
- 加入时间：生成访客时记录当日日期（`zh-CN`），存储于 localStorage。
- 昵称：若未输入，默认 `访客<访客ID后三位>`。

## 4) UI/样式基调
- 弹窗：蓝紫渐变顶栏 + 白色主体，圆角 24px 左右，卡片式信息块；文字为中文，保持现有项目的黑白简洁风主体。
- 图标：Font Awesome 占位（用户/日历/对话/锁）。

## 5) 后续可补充/调整
- 对话数量：接入真实接口后展示实际条数。
- 隐私说明：根据法务/合规反馈更新文案。
- 小屏适配：必要时简化网格布局，堆叠卡片。
